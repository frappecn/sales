# 业务需求与流程

## 1. 业务角色
可能涉及消费者、客服、采购人员、仓库管理员、拣货员、复核员、配送调度员、骑手、门店/仓负责人、财务人员和总部运营人员。实际岗位与权限矩阵待业务确认。

## 2. 核心流程

### 2.1 商品与价格
商品主数据优先复用 ERPNext Item、Item Group、UOM、Brand 等标准能力。销售可售状态、区域价格、门店可售范围、上下架和营销规则由 Sales 在不破坏标准模型的前提下扩展。

### 2.2 采购与收货
采购需求 → 采购订单 → 供应商送货 → 收货验收 → 入库。优先使用 ERPNext Buying、Purchase Order、Purchase Receipt 与库存账本。批次、保质期、称重商品和损耗规则需按实际业务确认。

### 2.3 库存与补货
库存以 ERPNext 库存交易和库存账本为权威来源。Sales 可增加库存查询、可售量计算、预占、补货建议等业务能力，但不得创建与 ERPNext 不一致的第二套实物库存账本。

库存至少区分：
- 实际库存：已完成入库且尚未出库的库存。
- 预占库存：已为订单锁定、尚未完成出库的数量。
- 可售库存：根据实际库存、预占、质检/冻结及业务规则计算的可销售数量。

具体计算口径、负库存策略和预占超时策略待确认。

### 2.4 消费者下单与订单管理
消费者选择配送地址和商品后提交订单。系统校验营业范围、商品可售、价格、库存和配送能力，再创建订单。订单状态与支付状态分离管理。重复提交、网络重试和支付回调必须幂等。

### 2.5 仓内履约
订单分配至履约仓 → 生成拣货任务 → 拣货 → 缺货/替代处理 → 复核 → 打包 → 出库交接。任务分配、波次拣货、称重差异和替代商品规则需结合实际操作确认。

### 2.6 配送
出库后创建配送任务，记录骑手接单、取货、配送中、送达、失败和异常。配送服务商、自有骑手或第三方运力模式待确认。

### 2.7 售后与退款
记录取消、缺货退款、拒收、退货、退款和赔付。退款必须关联原支付与订单，遵循支付渠道及 ERPNext 财务处理流程。

## 3. 必须设计的异常场景
- 商品售罄或库存并发不足。
- 订单重复提交或支付回调重复。
- 支付成功但订单状态未及时更新。
- 拣货缺货、商品损坏或称重差异。
- 骑手超时、配送失败、消费者拒收。
- 取消订单与拣货/出库并发发生。
- 退款失败、部分退款和重复退款。
- 网络中断、后台任务重试和消息重复消费。

## 4. 业务确认原则
所有未确认的金额、时限、状态流转、责任归属和运营规则均列入待确认事项。不得仅凭行业惯例直接固化。
