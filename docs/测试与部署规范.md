# 测试与部署规范

## 1. 测试层级
- 静态检查：格式、类型、代码规范和依赖检查。
- 单元测试：业务计算、状态机、权限和边界条件。
- 集成测试：DocType、Hooks、后台任务、ERPNext 单据交互。
- 端到端测试：下单、支付、拣货、出库、配送、售后完整链路。
- 回归测试：库存账本、财务凭证、权限隔离和历史流程。

## 2. 关键测试场景
重复下单、重复支付回调、库存并发预占、预占超时释放、缺货、订单取消与出库竞争、部分退款、配送失败、后台任务重试、跨网点数据权限。

## 3. 环境
开发、测试和生产环境隔离。不得使用真实客户敏感数据进行普通开发测试。密钥与配置不得提交到 Git。

## 4. 部署
使用受支持的 Frappe Bench 部署方式。先在测试环境执行迁移、构建和回归测试，再发布生产。记录应用版本、依赖版本、Commit SHA、迁移记录和备份位置。

## 5. 质量声明
没有真实运行的测试不得标记为通过。没有真实 Bench 环境时，只能说明完成代码审查或静态检查，不得声称已完成安装、迁移、构建或集成验证。
