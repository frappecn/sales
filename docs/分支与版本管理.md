# 分支与版本管理

## 1. 分支职责
- `main`：稳定发布主线，只合并已验证的发布版本。
- `develop`：功能集成主线。
- `test`：候选版本与回归验证分支。
- `feature/<topic>`：从 develop 创建，合并回 develop。
- `hotfix/<topic>`：从 main 创建，修复验证后合并回 main，并同步回 develop 与 test。

分支名称使用小写英文和短横线，不使用下划线。

## 2. 常规流程
feature → develop → test → main。每次合并通过 Pull Request，描述目的、变更、风险、测试结果和关联事项。

## 3. 提交规范
格式：`<type>: <中文简述>`。前缀使用英文，描述和提交正文使用中文。正文说明变更背景、实现内容、影响范围和验证情况。

允许类型：feat、fix、docs、refactor、test、chore、build、ci、perf、revert。

## 4. 版本
采用语义化版本 MAJOR.MINOR.PATCH。未形成稳定生产版本前可使用 0.x。发布时记录 Sales、Frappe、ERPNext 的 Commit SHA、依赖锁定信息、数据库迁移说明和回滚方案。

## 5. 保护
禁止未经授权强制推送 main、develop、test。分支保护、必需检查和审批规则在仓库权限允许后配置。
